# Pitch-weighted velocity averages by facial hair format

## Goal
The velocity charts currently read `averages-full.csv`, where each value is an **average of per-start averages**. That's wrong: a 40-pitch start counts the same as a 110-pitch start. We have pitch-by-pitch Savant data, so we can compute **true pitch-weighted averages** instead — pool every pitch of a format, then divide once.

Scope:
- **Velocity only.** K/9 in the sheet is already computed from totals (`SO × 9 / IP`), so it's correct as is.
- **Game score stays out** — it's one value per start, its math doesn't change.
- **Postseason games are included.**

## Approach
A plain Node script (ESM, same style as `convertCsv.js`) reads the CSVs, pools pitches in memory, and writes a generated TypeScript file. **No database** — see "Why not a database" at the end. The script is a pure function of its inputs: same CSVs in → byte-identical `velocities.ts` out. Run it by hand whenever the data changes; it holds no state between runs.

## Inputs

Three CSVs. The script only reads the columns listed; everything else is ignored.

### 1. Pitch data files (Savant exports) — `src/data/savant/*.csv`
One row per pitch. The script reads an **explicit array of filenames** (never a glob), and streams each into the same accumulator.

- **Frozen history:** one write-once file covering 2019 through the last completed season (currently `pitches.csv`).
- **Current season:** one file per season going forward (`pitches-2027.csv`, …), re-exported as the season progresses, then frozen when it ends. We do **not** fold new seasons into the big file.
- During development the array is just the test slice `pitches_2026.csv` (see Housekeeping).

Columns used (matched by **name**, so column order between exports doesn't matter):

| Column | Use |
|---|---|
| `game_date` | `YYYY-MM-DD`. Join key to `starts.csv`. Exactly one game per date. |
| `game_year` | Season. Optional sanity-check that a season file holds only its own year. |
| `pitch_name` | The pitch type, as a readable label — e.g. `4-Seam Fastball`, `Slider`, `Changeup`. This is the bucket key: each format gets a separate average per pitch type. Read from this column rather than `pitch_type` (see note). |
| `release_speed` | Out-of-hand velocity. Rows with an empty value are skipped. |

Notes:
- `pitch_type` and `pitch_name` hold the **same** pitch-type information — `pitch_type` is the short code (`FF`, `SL`, `CH`), `pitch_name` the readable label. We bucket by pitch type either way; we just read the `pitch_name` column because each Savant export carries a UTF-8 BOM on the first header (`pitch_type`), which corrupts that key. We read none of the first column, so the BOM is otherwise harmless.
- **Overlap guard:** if the same `game_date` appears in two input files, **fail loudly**. Pooling silently absorbs duplicates, so this is the safety net against accidentally listing an overlapping or subset file.

### 2. Date → format map — `src/data/starts.csv` (you maintain this)
One row per start. This is the only place facial-hair format lives; Savant has none of it.

| Column | Use |
|---|---|
| `Date` | `YYYY-MM-DD` or `M/D/YYYY` (both normalized to ISO). |
| `Format` | Must exactly match one of the format names in `averages-full.csv`. |

The script **fails loudly** on an unknown format name or a date listed twice, so a typo stops the run instead of skewing an average. Extra columns are ignored.

### 3. Format order — `src/data/averages-full.csv` (read-only here)
We read only the **`Format` column**, in spreadsheet row order, to fix the order of the output arrays so they line up with the existing chart labels and label images. The rest of this file is still used by the game-score and K/9 charts and is left untouched.

## Output — `src/data/velocities.ts`
Generated; do not edit by hand. Arrays are aligned to `formats` order. Pitch keys are sorted alphabetically for stable diffs. `null` velocity where a format threw no pitch of that type.

```ts
// Generated by aggregatePitches.js from the Savant pitch files. Do not edit by hand.
// Pitch-weighted velocity averages: every pitch of a format is pooled, then divided once.

export const formats = [
  'Clean shaven',
  'Stache only',
  'Stache + soul patch',
  'Stubble + stache',
  'Short beard',
  'Full beard',
  'Long beard',
  'Mountain man beard',
] as const;

export const velocities = {
  '4-Seam Fastball': [97.2, 97.4, /* … one per format … */ null],
  Changeup: [/* … */],
  'Knuckle Curve': [/* … */],
  Sinker: [/* … */],
  Slider: [/* … */],
  Sweeper: [/* … */],
} as const; // avg, 1 decimal, null if none

export const pitchCounts = {
  '4-Seam Fastball': [412, 388, /* … */ 0],
  // …
} as const; // sample size per format, 0 if none; handy for tooltips

export const starts = [2, 13, /* … one per format … */] as const; // distinct game dates per format
```

## Script behavior (`src/data/aggregatePitches.js`)
1. Read the `Format` column of `averages-full.csv` → the ordered format list + a set of valid names.
2. Read `starts.csv` → `Map<date, format>`. Validate: unknown format or duplicate date throws.
3. Stream each pitch file in the explicit array:
   - Throw if a `game_date` was already seen in an earlier file (overlap guard).
   - `format = map.get(game_date)`; if missing, record the date as unmatched and skip.
   - Skip empty `release_speed`.
   - Accumulate `acc[format][pitch_name] = { sum, count }` and add the date to that format's date set.
4. Pivot into `velocities` / `pitchCounts` / `starts` and write `velocities.ts`.
5. Print a summary:
   - pitches matched / total
   - starts per format
   - **Savant dates with no format** — starts still needing a label in `starts.csv`
   - **`starts.csv` dates with no Savant pitches** — typos or date-format problems

## Wiring up
- `package.json`: add `"data:pitches": "node src/data/aggregatePitches.js && prettier --write src/data/velocities.ts"`. Commit the generated `.ts`, same as the current `npm run data` flow — keep it out of the Parcel build so deploys stay fast.
- `src/data/newChartData.ts`: point the velocity datasets at the new `velocities` object instead of `averages[...]`. Keys rename: `'4 seam'` → `'4-Seam Fastball'`, `'Change'` → `'Changeup'`, `'Knuckle curve'` → `'Knuckle Curve'`; Sinker / Slider / Sweeper unchanged. Game score and K/9 keep reading `averages-full`.
  - **Data keys vs. display labels are separate things.** `velocities` is keyed by Savant's `pitch_name` spelling; that's what these lookups use. The `label:` strings shown on the chart (`'Four-seam'`, etc.) are set by hand and independent — they can keep whatever spelling you like, Savant's spelling never reaches the screen. This is a **one-time rename** (accepted); after it, re-running the data script refills the same keys and needs no further graph edits. We keep Savant's spelling as the key rather than translating to the old spellings, to avoid maintaining a perpetual name-mapping layer.
- Later, when promoting to prod, do the same in `src/data/chartData.ts`.

## Season rollover
When a season ends: freeze its file (stop re-exporting it), add the next season's filename to the script's array, and keep adding that season's starts to `starts.csv`. Every pitch file is write-once; the big file is never rewritten.

## Housekeeping (cleanup when building)
- **Delete `savant/pitches_2026.csv`** once development is done — it's a 2026 test slice and a subset of the frozen file, so leaving it in the array would double-count.
- **Delete `src/data/db.js` and `database.sqlite`** (untrack the latter) — leftovers from the abandoned SQLite experiment.
- Optional: rename the frozen file `pitches.csv` → `pitches-2019-2026.csv` for symmetry with the per-season files.
- The old `--year` flag is dropped; per-season files replace it.

## Verification
1. **Start with `pitches_2026.csv` only.** 2026 is what's live in prod, so the output is checkable against the real site.
2. Run `npm run data:pitches` and read the summary. The two "no-match" lists should be empty or only dates you expect.
3. New values should sit within a few tenths of the old `averages-full.csv` numbers; a big jump means a mapping bug.
4. Spot-check one cell by hand: filter a pitch file to one format's dates and average its `release_speed` for one pitch type.
5. Re-run and confirm `velocities.ts` is byte-identical (idempotent — an empty `git diff` is the "nothing changed" signal).
6. `npm start` and confirm the velocity charts render with the right labels, image order, and `null` gaps.
7. `npm run lint`.

## Why not a database
We considered loading the pitches into SQLite (two tables: `starts` keyed by date, and `pitches` joined on date). We dropped it because the data store here is a **derived, rebuilt-from-CSV artifact**, so the update anomalies that normalization protects against can't occur — if a value is wrong, fix the CSV and regenerate. A single pitcher also makes a `players` table pointless, and `format` has no attributes worth a `formats` table. The model still survives without the DB: the two "tables" are just the two input sources (pitch files + `starts.csv`), the join becomes `map.get(game_date)`, and the `GROUP BY (format, pitch_name)` becomes the in-memory accumulator. If an explorable dataset is ever wanted, that's a separate toy — build it alongside, not in the chart pipeline.
