# Pitch-weighted velocity averages by facial hair format

## Context
Velocity charts currently use `averages-full.csv`. Each value there is an average of per-start averages, so a 40-pitch start counts as much as a 110-pitch start. We now have pitch-by-pitch Savant data, so we can compute true per-pitch averages for each format.

Scope:
- **Velocity only.** K/9 in the sheet is already computed from totals (`SO × 9 / IP normalized`, e.g. 12×9/10.67 = 10.12), so it's correct as is.
- **Game score stays out**, per your answer: it's one value per start and its math doesn't change.
- **Postseason games are included.**

What the data looks like:
- `src/data/savant/pitches.csv` has 21,162 pitches, all Cease, across 222 games from 2019-07-03 to 2026-09-18.
- There's exactly one game per `game_date`, so the date alone is a safe join key.
- `pitches_2026.csv` is just the 2026 slice of `pitches.csv` (2,895 rows). We can filter by `game_year` from the full file instead of maintaining two inputs.

## Approach

### 1. Export the per-start sheet → `src/data/starts.csv` (you do this)
We need one row per start, with at least these columns:
- `Date`, as `YYYY-MM-DD`. The script will normalize `M/D/YYYY` too.
- `Format`, using the same strings as `averages-full.csv` (`Clean shaven`, `Stache only`, …).

Extra columns can stay; the script ignores them.

### 2. New script `src/data/aggregatePitches.js` (Node, ESM, same style as `convertCsv.js`)
1. **Load the date→format map.** Read `starts.csv` with `csvtojson`, which is already a dependency, into `Map<date, format>`. Fail loudly on unknown format names or a date listed twice.
2. **Set the format order.** Read the `Format` column of `averages-full.csv` so the output arrays line up with the existing chart labels and images.
3. **Stream the pitches.** Use `csv({ includeColumns: /game_date|game_year|pitch_name|release_speed/ }).fromFile(...).subscribe(row => …)`, which streams row by row instead of loading the file into memory.
   - Use `pitch_name`, not `pitch_type`. The file starts with a UTF-8 BOM that would corrupt the first header (`pitch_type`), and `pitch_name` gives readable keys anyway.
   - Look up `format = dateMap.get(row.game_date)`. If it's missing, record the date as unmatched and skip the row.
   - Accumulate `acc[format][pitch_name] = { sum, count }`, skipping empty `release_speed`.
   - Track the set of dates per format, so we have a start count.
4. **Year filter.** An optional `--year=2026` flag (read via `process.env.npm_config_year`, mirroring the existing `npm_config_new` pattern) replaces the separate 2026 file and produces `velocities-2026.ts`.
5. **Write `src/data/velocities.ts`:**
   ```ts
   // Generated by aggregatePitches.js. Do not edit by hand.
   export const formats = [...] as const;
   export const velocities = { '4-Seam Fastball': [97.1, ...], Slider: [...], ... } as const; // avg, 1 decimal, null if no pitches
   export const pitchCounts = { '4-Seam Fastball': [412, ...], ... } as const; // sample size, handy for tooltips
   export const starts = [2, 13, ...] as const;
   ```
6. **Print a summary:**
   - pitches matched / total
   - starts per format
   - **Savant dates with no format.** These are sheet gaps to fill, or relief outings you may want to add.
   - **Sheet dates with no Savant pitches.** These are typos or date-format problems.

### 3. Wire it up
- `package.json`: add `"data:pitches": "node src/data/aggregatePitches.js && prettier --write src/data/velocities*.ts"`.
  - Commit the generated `.ts`, same as the current `npm run data` flow, rather than hooking it into the Parcel build. The data rarely changes, and this keeps the deploy build fast.
- `src/data/newChartData.ts`:
  - `veloData` and `breakingVeloData` import from `./velocities` instead of `averages['4 seam']`, etc. Key names change (`'4 seam'` → `'4-Seam Fastball'`, `'Change'` → `'Changeup'`, `'Knuckle curve'` → `'Knuckle Curve'`). Sinker, Slider and Sweeper keep their names.
  - `gameScoreData` and `k9data` keep reading `averages-full`.
- Later, when promoting to prod, do the same in `src/data/chartData.ts` with `velocities-2026.ts`.
- Optionally, drop the velocity columns from the `COLUMNS` list in `convertCsv.js` once nothing reads them.

## Critical files
- new: `src/data/aggregatePitches.js`, `src/data/starts.csv` (exported by you), generated `src/data/velocities.ts`
- edit: `package.json`, `src/data/newChartData.ts` (later `chartData.ts`)
- reference: `src/data/convertCsv.js` (output and flag conventions to copy)

## Verification
1. Run `npm run data:pitches` and check the summary. Unmatched-date lists should be empty, or only contain dates you expect.
2. Sanity check: the new values should be within a few tenths of the old `averages-full.csv` numbers. A big jump means a mapping bug.
3. Spot-check one format by hand, e.g. filter `pitches.csv` to that format's dates in a quick one-off and average 4-seam `release_speed`.
4. Run `npm start` and confirm the velocity charts render with the right labels, image order and gaps (`null`) where a pitch wasn't thrown.
5. Run `npm run lint`.
